# Деплой на Render

## Что разворачивается

| Ресурс | План | Зачем |
|---|---|---|
| Web Service (Node) | **Starter**, не Free | Free усыпляется через 15 мин простоя и **не поддерживает диск** |
| PostgreSQL | Free или Starter | Free живёт 30 дней, потом удаляется |
| Disk 1 GB на `/var/data` | входит в Starter | хранит загруженные рендеры |

## Быстрый путь — через blueprint

1. Залей репозиторий на GitHub.
2. Render → **New → Blueprint** → выбери репу. Он прочитает `render.yaml`
   и создаст сразу web-сервис, базу и диск.
3. После первого деплоя зайди в Environment и впиши `NEXTAUTH_URL` —
   реальный адрес сервиса, например `https://dripcases.onrender.com`.
   Без него логин будет редиректить не туда.
4. Передеплой.

`DATABASE_URL` подставится из базы автоматически, `NEXTAUTH_SECRET`
Render сгенерит сам.

## Ручной путь

Если не хочешь blueprint:

**Build Command**
```
npm ci && npx prisma generate && npx prisma migrate deploy && npm run build
```

**Start Command**
```
npm start
```

**Environment**
```
NODE_VERSION     = 20.18.0
DATABASE_URL     = <Internal Database URL из Render Postgres>
NEXTAUTH_SECRET  = <openssl rand -base64 32>
NEXTAUTH_URL     = https://<твой-сервис>.onrender.com
UPLOAD_DIR       = /var/data/uploads
```

**Disk**: Name `uploads`, Mount Path `/var/data`, 1 GB.

**Health Check Path**: `/api/health`

Бери **Internal Database URL** — он быстрее и не жрёт внешний трафик.
External нужен только чтобы подключиться с ноута.

## Сид на проде

Миграции накатываются автоматически при каждом билде. Демо-данные — нет.
Один раз, через Render Shell (вкладка Shell у сервиса):

```
npm run db:seed
```

**Сразу после этого смени пароль админа** — в сиде он `admin123`.

## Загруженные рендеры

Локально файлы падают в `public/uploads/` и раздаются Next'ом напрямую.

На Render переменная `UPLOAD_DIR=/var/data/uploads` переключает запись на
персистентный диск, а раздачу — на роут `/api/uploads/[...path]`.
Переключение автоматическое, ничего в коде менять не надо:
логика в `src/lib/storage.ts`.

Почему не `public/`: эта папка вшивается в билд-артефакт, а файловая
система контейнера эфемерная — всё записанное туда исчезнет при первом
же редеплое или рестарте.

### Если перерастёшь диск

1 ГБ хватит на пару сотен рендеров. Когда станет мало — переезжай на
Cloudflare R2 или S3: меняется только `src/lib/storage.ts` и роут
аплоада, остальной код работает с путями и не заметит разницы.

## Подводные камни

**Free-план web-сервиса.** Усыпляется через 15 минут без трафика,
первый запрос после сна ждёт ~30 секунд. И диска там нет вообще —
аплоад работать не будет. Для демо клиенту сойдёт, для продакшена нет.

**Free-база живёт 30 дней.** Потом Render её удаляет. Перед дедлайном
проверь, что она не истекает, или сразу бери Starter.

**Холодный билд долгий.** Первая сборка 4–6 минут, последующие быстрее
за счёт кеша.

**Регион.** В `render.yaml` стоит `frankfurt` — ближайший к Украине.
База и сервис **обязаны** быть в одном регионе, иначе Internal URL
не сработает.

## Проверка после деплоя

```
GET /api/health   → {"ok":true,"db":"up"}
```

Если `db: down` — `DATABASE_URL` не подхватился или база в другом регионе.
